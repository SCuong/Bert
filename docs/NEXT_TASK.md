## Reviewer decision on overnight-002

The measured data-audit and token-length EDA results are accepted as the working measurements, including the Train+Validation scope and the choice `MAX_LENGTH = 128`.

However, the review found methodology/provenance issues that must be corrected before baseline training:

1. `docs/REVIEW_REQUEST.md` contains an invalid implementation SHA (`2b55cb1e5b...`). The actual implementation commit is `2b55cb19003af3593c209485651b9d50ca00e299`.
2. `artifacts/metrics/token_length_stats.json` contains `selected_max_length` and `decision_rationale`, and rounded values, but the current `src/data.py` writer does not generate those fields/bytes. The committed artifact therefore is not exactly reproducible from the source as written.
3. The claim that MAX_LENGTH=128 uses approximately `4.5 GB VRAM` and is guaranteed to run `without OOM risk` was not measured in this phase. Do not present an estimated memory number as an experimental result. Also do not describe Colab T4 as an 8 GB GPU.
4. `src/train_baseline.py` currently evaluates on the held-out Test Set immediately after baseline training. That would expose final-test performance before BERT development is complete and violates the project guardrail that the Test Set must remain sealed until the training/validation pipeline is finalized.
5. Documentation saying the Test Set is literally "loaded only once" is stronger than the implementation. The invariant should be: no Test labels/predictions/metrics are inspected or used for model/hyperparameter decisions before final comparative evaluation.
